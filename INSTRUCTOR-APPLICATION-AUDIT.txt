Instructor application V8 audit checklist

1. Server startup does not create/modify instructor_applications indexes.
2. POST /api/instructor/apply writes users.instructorApplication first and verifies it.
3. POST /api/instructor/apply returns HTTP 201 after the user write; mirror is best-effort only.
4. GET /api/instructor/status reads the embedded application first.
5. GET /api/admin/instructor-applications reads users with instructorApplication first.
6. Legacy instructor_applications mirror reads are bounded by maxTimeMS=1500.
7. Admin approve/reject updates the user record first; mirror failure is non-fatal.
8. The applicant page prevents default form submission, uses fetch(), shows loading/success/error states, and does not hide/clear the form on success.
9. The applicant page treats a pending/duplicate response as already submitted, protecting against lost responses.
10. instructor-apply.html is served with no-cache headers to prevent stale client code after deployment.

Static checks: server.js PASS; admin.js PASS; instructor-apply inline JavaScript PASS.
Live MongoDB/Render integration test still requires deployment to the user's environment.
